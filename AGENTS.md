# Инструкции для программирующих агентов

## Перед изменениями

Прочитайте [README](README.md) и релевантные части [архитектуры](docs/ARCHITECTURE.md). Для деплоя используйте [инструкцию](docs/DEPLOYMENT.md). Проверяйте текущий код: числовые значения в документации могут отстать от последующих изменений.

## Ограничения проекта

- Сохраняйте статическую публикацию на GitHub Pages без backend, ключей, обязательного CDN и сборки. Не вводите зависимости без необходимости задачи.
- Используйте относительные пути. Не добавляйте ссылки на абсолютные пути компьютера в игровой код.
- Изображения размещайте в `src/assets/`. Сохраняйте прозрачность, размеры и привязку кадров; при изменении атласов проверяйте UV-области.
- Не удаляйте пользовательские изменения и не переписывайте историю Git. Коммит, push и публикацию выполняйте только в рамках запроса пользователя.
- Не меняйте баланс, вероятность верного слова и веса словаря попутно с визуальными исправлениями.
- Пауза, настройки, intro и over не должны продвигать игровое время или физику. Счёт 0 не означает проигрыш.
- Сохраняйте совместимость настроек localStorage и работу при недоступном хранилище.
- Не освобождайте общие материалы/текстуры при удалении одного объекта. Сохраняйте признак `userData.shared`.
- Правки CSS проверяйте с учётом последующих media-переопределений. Сохраняйте мобильные кнопки, safe-area, прокрутку настроек и управление свайпами.
- Не допускайте двойного действия от pointerdown и click. Клавиатурное управление также должно работать.
- Обновляйте документацию вместе с изменениями поведения, формата данных, запуска или деплоя.

## Проверки

Для изменения логики выполните `npm test` и синтаксическую проверку затронутых JS-файлов. Добавляйте тесты на существенное новое поведение, особенно границы уровней, счёт, паузы и настройки. Для небольшого визуального исправления достаточно прицельной проверки в браузере; тесты, повторяющие CSS, не нужны.

Проверьте соответствующие сценарию состояния: старт, игра, прыжок, смена дорожки, пауза/настройки, проигрыш и рестарт. Для мобильных правок используйте портрет 390×844, короткий экран 390×664 и landscape 844×390; при необходимости также 320px по ширине. Указывайте, если проверялась только эмуляция, а не физическое устройство. После проверки возвращайте временно изменённый размер браузера.

В отчёте кратко опишите результат, проверки и реальные ограничения. Не утверждайте, что сайт опубликован, если изменились только локальные файлы.

## Среда разработки

Проект может открываться в Windows по UNC-пути WSL. В таком случае npm через CMD иногда теряет рабочую директорию. Используйте прямые команды `node scripts/serve.js`, `node --test tests/logic.test.js` либо Ubuntu-терминал с Node.js. Git можно вызывать через `wsl git -C /home/smitevils/projects/Samsa-Language-Run ...`. Это путь текущего рабочего окружения, а не требование приложения.

Python и eSpeak нужны только для пересборки словаря. Не запускайте генератор ради изменения интерфейса: это может массово поменять транскрипции.
