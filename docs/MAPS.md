# Добавление карты

Карты — JSON-объекты в `src/maps/`. Код игры не содержит ветвлений по имени карты.

1. Скопируйте `park.json` или `museum.json`, например в `gallery.json`.
2. Задайте уникальный `id` (`gallery`), `label` для настроек, `title` для HUD, `description` и `collisionHint`.
3. Добавьте имя файла в массив `maps` в `src/maps/index.json`. Порядок определяет список в настройках. `default` — id карты по умолчанию.
4. Замените цвета, спрайты и декор. PNG храните в `src/assets/`. Новые файлы не требуют JS-регистрации.
5. Запустите `node --test tests/logic.test.js`, затем проверьте обе ориентации экрана и смену карты в настройках.

## Общие ограничения

У каждой карты ровно **5 вариантов бокового декора**, **2 барьера** и **3 встречных персонажа**. Проверка схемы выполняется перед загрузкой изображений. Несуществующие спрайты, дубли id и неправильные координаты вызывают ошибку загрузки с деталями в консоли.

Общий `layout` в index.json задаёт длину цикла: rows × spacing (18 × 7). По умолчанию на каждой стороне 18 объектов. В карте можно задать `"scenery": {"leftDensity": 0.6, "rightDensity": 0.6, "sideX": 9.5}`. Плотности независимы, от 0 (нет объектов) до 1 (полный бюджет), по умолчанию 1. Число объектов на стороне — round(rows × density); они равномерно распределены по всему циклу, включая стык при возвращении за горизонт. sideX — расстояние центров декора от оси дороги, по умолчанию из layout. Учитывайте половину ширины спрайта, чтобы его край не перекрывал арык. В махалле 11 объектов с каждой стороны, центры отнесены на 9.5. Швы пола и препятствия от scenery не зависят.

## Поля карты

- `indoors`: true — тёплый интерьер, false — уличный суточный цикл.
- `colors`: `ground`, `road`, `line`, каждый в формате #RRGGBB.
- `sprites`: словарь именованных областей атласов.
- `decor`: пять вариантов: спрайт либо небольшая группа примитивов.
- `obstacles`: массивы `barrier` (2) и `person` (3). Только спрайты. Скорости и правила столкновений общие для всех карт и задаются игрой.
- `environment`: необязательные неподвижные примитивы для стен, потолка и дальнего фона.

Пример описания спрайта (координаты от левого верхнего угла):

```json
"sprites": {
  "vase": {
    "file": "museum-exhibits.png",
    "reference": [2048, 683],
    "rect": [57, 66, 340, 601]
  }
}
```

`reference` — размеры системы координат атласа, `rect` — x, y, ширина, высота. Изображение может иметь другое фактическое разрешение; пропорции и раскладка должны совпадать. Отдельную картинку используйте с rect [0, 0, ширина, высота]. Вариант декора или препятствия: `{"sprite":"vase","height":4.6}`. Высота измеряется в игровых единицах; ширина вычисляется автоматически.

Вместо sprite у декора допустим `parts`:

```json
{"parts":[
  {"shape":"box","color":"#34594d","position":[0,1.8,0],"size":[0.1,3.6,0.1]},
  {"shape":"sphere","color":"#ffe4a4","position":[0,3.72,0],"radius":0.24,"emissive":true}
]}
```

Для box можно опустить shape. Координаты parts локальные, environment — мировые. Не добавляйте сложные модели в декор без проверки производительности: равное число позиций не гарантирует равное число draw calls.

## Загрузка и ресурсы

`map-scene.js` — общий построитель, `locations.js` — валидация, слоты и подбор вида препятствия. Атласы загружаются один раз на файл, геометрии и материалы примитивов переиспользуются. Все зарегистрированные карты создаются при запуске, но видима и движется только выбранная. При большом числе карт можно отдельно внедрить ленивую загрузку; сейчас её нет. Материалы спрайтов общие и не освобождаются при удалении отдельного препятствия.

Смена карты не сбрасывает счёт, слово, время или физику: активное препятствие получает соответствующий вариант новой карты. Старое сохранение с удалённой картой переходит на default.

`chorsu.json` — пример третьей карты без изменений игрового JS: два новых атласа, пять прилавков, три персонажа и два барьера из областей с товарами. Рынок использует уличное освещение и общий layout.

## Дальний план

`environment` поддерживает box, sphere, dome (верхняя полусфера), cylinder и cone. Для круглых форм задайте radius и segments (3–32, по умолчанию 16); для cylinder/cone также height. У cylinder необязательный radiusTop задаёт верхний радиус. scale [x,y,z] меняет пропорции, rotation [x,y,z] — углы в радианах, flatShading: true подчёркивает грани. Фон неподвижен, не участвует в столкновениях и бюджете бокового декора. Геометрии одинаковых форм переиспользуются. Примеры — телебашня и купол в park.json, павильон Чорсу в chorsu.json.
